# 随包权重说明

本目录提供一份动作跟踪训练初始化权重、一份适配当前 Dex 本体的站立基线及其校验 JSON，以及一份站立参考权重 `standing_2000.pt`。

| 文件 | 来源与用途 | 使用说明 |
| --- | --- | --- |
| `wbt_model_46400.pt` | 软件包提供的预制全身动作跟踪权重；通过 `LOAD_CKPT` 初始化新动作训练 | 目标动作仍需训练并验证 |
| `standing_baseline.pt` | 站立基线；用于当前本体的站立播放、默认部署演示，以及通过 `LOAD_CKPT` 初始化站立微调 | 可用于 Isaac 与 MuJoCo 站立，持续运行存在水平漂移 |
| `standing_baseline.json` | 上述站立基线的文件校验与运行配置记录 | 与 `standing_baseline.pt` 配套保留 |
| `standing_2000.pt` | 据训练记录，以站立基线初始化，在 4096 个并行环境下训练 2000 次迭代所得的站立参考权重 | 站立效果可用，用于站立效果对比 |

训练、播放、导出和部署命令见 [Dex-Mimic 使用说明](../../README.md)。约 3000 次迭代开始看到新动作效果是团队经验，不代表所有动作都已收敛。建议在新动作跟踪效果稳定后，以 `standing_baseline.pt` 初始化，使用 `dataset/standing/standing.npz` 单独微调站立头，评估站立稳定性和水平漂移；确认效果后，再与动作头合并导出，并检查站立、动作及两者切换时的表现。

## standing_baseline.json 的作用

这份 PT 没有内嵌模型与执行器契约，配套 JSON 用于记录并校验运行配置：

- PT 文件的 SHA256，确认加载的是同一份权重。
- 本体模型和资产的 SHA256，确认 URDF、MJCF 与网格版本匹配。
- Isaac 运行控制周期，以及 PD、armature 和力矩上限等执行器配置。这里的 `control_dt=0.02` 不表示 ROS 部署周期；部署按真机实测要求每 10 ms 重新推理，见 [动力学说明](../../../docs/model_and_dynamics.md#为什么部署至少需要-100-hz)。
- 权重来源说明。

当前加载器会检查 PT 哈希及运行配置。JSON 用于校验，不会自动修改仿真参数，也不等同于完整训练配置。不要在模型变更后只改 JSON 来跳过检查。

预制动作跟踪权重通过 `LOAD_CKPT` 显式初始化训练，不使用站立基线的直接加载例外，因此没有对应 JSON。站立基线也可通过 `LOAD_CKPT` 初始化站立微调；该入口加载模型权重及兼容的归一化状态，不恢复优化器状态。

## WBT 训练成功后如何保存

使用当前训练代码从 `wbt_model_46400.pt` 初始化后，新生成的 checkpoint 会在 PT 内部保存 `infos.dex_contract`，包含模型、资产、控制周期和执行器配置。**这类新 PT 无需再创建与 standing_baseline.json 同用途的外置 JSON。** 内置契约检查配置一致性，动作效果需通过回放和物理仿真评估。

确认动作效果后，应保留新训练生成的 checkpoint，保留原始 `wbt_model_46400.pt` 作为初始化来源，并更新本说明：记录新权重文件名、对应参考动作、训练迭代数，以及 Isaac、MuJoCo 的实际验证结果。训练次数本身不能代替验证；至少说明播放时长、是否跌倒、跟踪效果与漂移情况。

如果要将新权重加入发行包或设为默认动作，还需按使用说明重新导出 ONNX、生成部署包，并更新对应文档。部署包有自己的 `bundle.json`，与这里为站立 PT 配套的校验 JSON 用途不同。

只有需要直接使用其他缺少内置契约的旧 PT 时，才需要单独处理兼容记录和加载逻辑；当前加载器只为这里的站立基线提供了例外，并不会自动读取任意同名 JSON。
